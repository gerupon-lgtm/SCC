# 実装タスクとトレーサビリティ

## 前提（仮置き）

- 【想定】素のJS（ES Modules）、ビルドなし、`node --test`
- 【想定】高速版（F-003）の方式は `scc-core-spec.md` 6章。測定の結果次第で見直す
- 【想定】音声への変換は単純平均（同5章）。音質の改善は後続
- 【要確認】IKASCC照合、DAW方式、正式名称、公開名義（実装は止めない）
- 日時・タイムゾーン、DB、認証、共有URLは該当なし

## 技術的に難しい点（進言。検証範囲は外しません）

1. **MAME本物との照合（T-006）**：MAMEのチップ部分（k051649.cpp）は、MAME本体の仕組みに依存します。単体で動かす小さなC++の枠を作る必要があり、環境で動くかは未確認です。
   - 案A（推奨）：k051649.cppの計算部分だけを取り出し、小さな枠で動かして出力を記録する（本物のコードを使うので、最も確かな照合になる）
   - 案B：k051649.cppを読みながら、別に書いたJSで照合する（手軽だが、読み違いを検出できない）。案Aが無理だったときの代案として、進言のうえ発案者が選ぶ
2. **完全一致の高速版（T-007）**：周波数の書き込みが音声ブロックの途中で入ったときの扱いが難しい。書き込みの位置は、音声サンプル単位に丸める【想定】。この丸めは、基準版でも同じ単位で行うので一致は保てる
3. **Android実機のWeb MIDI（T-002）**：Chrome for Androidの対応状況の情報が食い違っています（未確認）。先に実機で確かめます
