# MGSDRV 形式の MML の調査（T-108、2026-10-15）

発案者の手元の6曲（MSXplay 向けの MGSDRV 形式）を、このアプリで再生するための調査です。
印：【確認】一次資料で確かめた／【未】資料に書かれていない・未確認

## 結論

- 書き方（文法）は、作者自身の説明書でほぼすべて確かめられた
- ただし、**演奏中の細かい動き**（音量とエンベロープの掛け合わせ、デチューンの単位、スラーの鳴らし方、`k` の消え方）は資料に無い。MGSDRV のソースコードは公開されておらず、作者も失っている【確認】
- そのため、作り方は2つに分かれる（下の「作り方の選択肢」）

## 確かめた文法【確認】（MGSC 説明書より）

| 項目 | 内容 |
| --- | --- |
| トラック | 行頭の 1〜H。`#opll_mode 1` では 1〜3 が PSG、4〜8 が SCC、9〜e が FM、f がリズム |
| 1拍の長さ | 4分音符 = 48ステップ。`%n` でステップ数指定。テンポ `t`（57〜2047、初期120）は全トラック共通 |
| 時間の単位 | ドライバは 1/60秒の割り込みで動く。最短の音長は 14400÷テンポ 分音符 |
| `@s<n> = { 32個の16進 }` | SCC の波形（音色 0〜31）。値は符号付き8ビット |
| `@e<n> = { Mode,Noise, データ }` | エンベロープ。データの 0〜f は「その音量にして1カウント（1/60秒）待つ」。`音量:カウント`、`音量=カウント`（なめらかに変化）、`[ ]` 繰り返し、`@n` 音色の変更、`\n` 周波数の加算など。Mode・Noise は PSG 用（Mode 2 はノイズのみ） |
| エンベロープの終わり | 最後の音量のまま鳴り続ける（Wiki の旧版の記述） |
| `@n` / `@e<n>` | 音色の変更 / エンベロープを今の音色に写す（SCC・FM で有効） |
| `v` `o` `l` `q` `k` | 初期値 0・4・4・8・0。`q` は音長比 0〜8、`k` はキーオフ後に消える速さ（0が最速） |
| `&` | スラー（音程の直後のみ。タイとは別） |
| `^` | タイ（音長を足す） |
| `\n` / `@\n` | デチューン（−127〜127）/ 細かいデチューン（PSG・SCC では 128 で約半音） |
| `[n … \| … ]` | 繰り返し（n=0 で無限、省略は2）。`\|` は最後の回で抜ける。16重まで |
| `*n` / `*n = { … }` | マクロの呼び出し / 定義（0〜255、8重まで） |
| 大文字・小文字 | 区別しない（手元の `@E25`・`G2` も同じ意味） |

## 資料に無いこと【未】

1. `v` とエンベロープの値の掛け合わせ方（引き算か、掛け算か）
2. `\n`（デチューン）の SCC での単位（周波数の値にそのまま足すのか）
3. `&`（スラー）の鳴らし方（キーオフしない／エンベロープを最初からやり直さない、など）
4. `k`（キーオフ後の消え方）の具体的な時間

## 手元の6曲で使われている命令（確認済み）

`#opll_mode`、`#title`、`@s`、`@e`（大文字の `@E` を含む）、`*n` マクロ、`[n … | … ]`（`[0` 無限）、`t` `@n` `v` `o` `l` `\n`、音符・休符・`&`・`< >`。
トラックは 4〜8（SCC）が中心。TwinBee だけトラック1（PSG のノイズ、`@e30 = { 2,13, … }`）を打楽器に使う。

## 作り方の選択肢

| | A：説明書をもとに自分で解釈して鳴らす | B：本物の MGSDRV を Z80 の再現の中で動かす |
| --- | --- | --- |
| しくみ | MML を読んで、SCC・PSG のレジスタ書き込みに直す | MML を MGS に変換（mgsc）→ 本物の MGSDRV（Z80 の機械語）を動かし、出てきた SCC・PSG の書き込みを、このアプリのチップへ渡す（MSXplay と同じ考え方） |
| 正確さ | 資料に無い4点は推測。MSXplay と耳で比べて合わせる | MGSDRV そのものなので、演奏の動きは本物と同じ |
| 手間 | 中（文法は確定している） | 大（Z80 の再現、MSX の環境の最小限の再現、変換） |
| 使う外部のもの | なし | mgsc（ISC）、MGSDRV.COM（フリーソフト。配布は「アーカイブの内容を変更しない」条件。ファイルだけを抜き出して同梱してよいかは要確認。発案者が手元のファイルを読み込ませる形なら同梱しない） |
| 負荷 | 小 | Z80 の再現の分だけ増える（1/60秒ごとの処理で、重くはない見込み。未測定） |

## 採用：案B（2026-10-15、発案者）と、作った結果

| 部品 | 内容 | 確かめたこと |
| --- | --- | --- |
| `src/mgs/z80.js` | Z80 の再現 | ZEXDOC（Z80 の命令検査）の全67項目が OK（`node tools/zexdoc.js`、約4分）【確認】 |
| `src/mgs/cpm.js` | 最小限の CP/M | 本物の MGSC.COM（-e）が動き、手元の MML を MGS に変換できた（約0.1秒）【確認】 |
| `src/mgs/mgsdrv-host.js` | libkss（MSXplay）と同じ環境で MGSDRV を動かす | 本物の MGSDRV 3.20 で Final Attack が鳴った。自作の短い MML で、C4 の値（427）と1拍0.5秒をテスト【確認】 |
| `src/audio/scc-worklet.js` | 1/60秒（48,000Hzなら800サンプル）ごとの位置で MGSDRV を呼ぶ | PCの処理の重さ3%【確認】 |

分かったこと：
- MGSDRV は SCC のキー（0x8F）を一度も書かない。MSXplay の SCC の再現（emu2212）はリセット時に全チャンネルが有効なので鳴る。このアプリの SCC は MAME と同じく全チャンネル無効で始まるため、曲の開始時に 0x1F を書いて合わせた【MSXplay と同じ。実機は未確認】
- PSG への書き込み（TwinBee の打楽器など）は取り出せているが、PSG がまだ無いので鳴らない（F-018 で対応）
- MGSDRV.COM・MGSC.COM は同梱しない。画面で選ぶと、そのブラウザに保存する（どこにも送らない）
