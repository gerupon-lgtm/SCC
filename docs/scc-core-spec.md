# SCC中核の仕様（基準版の定義）

実装の根拠となる定義です。要件定義書4章の確認済み仕様と、MAMEの k051649.cpp（BSD-3-Clause）の動きにそろえています。
この文書を、コードとは別に保ちます。将来、他の言語やプラグインへ移すときの入力になります（要件6章の移植性）。

区分の記号：【確認】MSXの技術資料とMAMEの両方で確認済み。【MAME】MAMEのコードから読み取った動き。実機は未確認。【設計】この案件での設計判断。

## 1. 状態

チャンネルごと（既定5チャンネル）：

| 項目 | 範囲 | 初期値 | 区分 |
| --- | --- | --- | --- |
| frequency | 0〜4095（12ビット） | 0 | 【確認】 |
| volume | 0〜15（4ビット） | 15 | 【MAME】 |
| key | 真偽 | 偽 | 【確認】 |
| counter | 0〜31（波形の位置） | 0 | 【MAME】 |
| clock | -1〜frequency | 0 | 【MAME】（MAMEでは16ビット符号なしで、-1 は 65535。次の +1 で0に戻るので、動きは同じ） |
| sample | 整数（-1920〜1905） | 0 | 【MAME】 |

波形メモリ：1バンク32バイト、8ビット符号付き（-128〜127）。SCC互換モードのバンク数は4で、チャンネル4と5はバンク3を共有します【確認】。リセットでは波形メモリを消しません【MAME】。

## 2. 1クロックごとの動き（基準版）

```
tick():
  out = 0
  for ch in channels:
    if ch.frequency > 8:                      # 8以下は止まる【確認】
      ch.clock += 1
      if ch.clock > ch.frequency:
        ch.counter = (ch.counter + 1) & 31
        ch.clock = 0
      if ch.clock == 0:
        ch.sample = (ch.key ? wave[bank(ch)][ch.counter] : 0) * ch.volume
    out += ch.sample >> 4                      # 算術シフト。負の数は切り下げ【MAME】
  return out
```

- 止まっているチャンネルも、最後の `sample` を出力に足し続けます【MAME】
- 音量・キーの変更は、次に `sample` を読み直す瞬間まで音に出ません【MAME】
- 1つの波形が一周する時間は 32 ×（frequency+1）クロックです【確認】

## 3. 書き込み

| 操作 | 動き | 区分 |
| --- | --- | --- |
| 周波数の下位8ビット | `frequency = (frequency & 0xF00) \| v`、`clock = -1` | 【MAME】 |
| 周波数の上位 | `frequency = (frequency & 0x0FF) \| ((v << 8) & 0xF00)`、`clock = -1` | 【MAME】 |
| 音量 | `volume = v & 0xF` | 【確認】 |
| キー | チャンネルiの `key` = vのビットi（i = 0〜4） | 【確認】 |
| 波形 | 該当バンクのi番目に、vを符号付き8ビットで保存 | 【確認】 |
| テストレジスタ | 値を保存するだけで、動きは変えない（MVP） | 【設計】 |

`clock = -1` の次の1クロックで、`clock` は0になり、`counter` は進まずに `sample` だけ読み直されます【MAME】。

## 4. 出力の大きさ

1クロックの出力は整数の和 `out` です。浮動小数点にするのは最後の1回だけです（`out / 1024`、MAMEと同じ）【MAME】。5チャンネルの最大は約0.59です。チャンネルを増やしたときの余裕は、後処理の音量で調整します（`5 / チャンネル数`）【設計】。

## 5. 音声への変換（整数）【設計】

```
acc = 0
for each audio sample:
  acc += CLOCK                       # 3,579,545
  L = floor(acc / sampleRate)        # 48,000Hzなら74か75
  acc -= L * sampleRate
  sum = core.sumTicks(L)             # L クロック分の out の和（整数）
  y = sum / (L * 1024)
```

- 基準版（1クロックずつ）と高速版は、同じ `L` の列に対して、同じ `sum` を返します。これを完全一致で確かめます
- この変換は単純な平均です。高い音で折り返しノイズが出る可能性があります。音質の改善（フィルターなど）は後続で検討し、基準版と高速版の両方に同じ後処理をかけます

## 6. 高速版の考え方【設計】

チャンネルの出力は、`sample` を読み直す瞬間にだけ変わります。そこで、次の読み直しまでの残りクロック数 `r` を持ち、`r` ごとに足し込みます。

- `clock = -1` のとき：`r = 1`（読み直しで `counter` は進まない）
- それ以外のとき：`r = frequency - clock + 1`（読み直しで `counter` が進む）
- 止まっているとき（frequency が8以下）：読み直しは起きない
- 読み直しの後は、`frequency + 1` クロックごとに読み直す

1つの音声サンプル（約75クロック）の中の読み直しは、最大でも約8回です（frequency = 9のとき、計算値）。
